# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Masmorra do Carrasco" — a souls-like action RPG in plain Three.js (browser, ES modules). No build step, no npm dependencies, no linter; the only tests are the online-world server's (`npm test`). Three.js and its addons (GLTFLoader, SkeletonUtils, BufferGeometryUtils, RoomEnvironment) are vendored in `vendor/`; `three` is resolved through the import map in `index.html`. All in-game text, UI, and code comments are in Brazilian Portuguese — keep new ones in Portuguese.

## Running

```bash
npm start            # node server.js → http://localhost:5173 (PORT env var overrides)
npm test             # node testes/mundo.test.mjs — o servidor de mundo (MMO), por HTTP, sem navegador
masmorra.exe         # (ou o atalho na área de trabalho) sobe o servidor e abre o jogo em janela de app
dotnet publish launcher -c Release -o .    # recompila o masmorra.exe (SDK .NET 8)
```

**O launcher (`launcher/`, gera `masmorra.exe`)** prende o servidor ao terminal: o log aparece nele, e fechar a janela ou Ctrl+C desliga o jogo — um Job Object (`KILL_ON_JOB_CLOSE`) garante isso até se o launcher for morto à força. Ele reconhece o jogo já no ar pela rota `/__saude` do `server.js` (`quem: 'masmorra-do-carrasco'`) e, com a 5173 ocupada por outro programa (é a porta do Vite), sobe na próxima livre via `PORT` — o `server.js` sozinho cairia com `EADDRINUSE`. O ícone é desenhado por `launcher/gerar-icone.ps1`. É uma cópia enxuta do launcher do editor de cenas.

`server.js` is a minimal static file server (plus the save, LAN-room and online-world routes). It exists because ES modules won't load over `file://`. There is nothing to compile, so edits show up after a browser reload. To check a change, load the page and play or inspect it. `window.game` exposes the `Game` instance in the console for debugging (e.g. `game.player.pos`, `game.inventory.add('greatsword', 1)`).

**O estático é uma lista BRANCA** (`FRENTE` em `server.js`: `index.html`, `css`, `js`, `vendor`, `assets`). Pasta nova que a página precise carregar tem de entrar nela; `saves/` e `mundo/` ficam de fora de propósito (o servidor escuta em todas as interfaces).

**ONDE O JOGO RODA (`js/hospedagem.js`, 02/10/2026)** — são três peças: as CONTAS no Supabase, o JOGO no GitHub Pages (`https://felisbertojpg.github.io/MMO-Project/`, repositório `FelisbertoJPG/MMO-Project`, a raiz da branch `main`) e o SERVIDOR DE MUNDO em outro lugar (ainda não há: ver `TASKS-MMO.md`). O Pages só entrega arquivos, então lá não existe `/__save`, `/__lan/*` nem `/__mundo/*`. Uma sonda em `/__saude` no carregamento decide: com o `server.js` por trás, tudo como sempre; sem ele (`temSaveEmArquivo()` falso), o save da Jornada vai para o `localStorage` (mais a nuvem, com conta), a sala só existe pela internet, e o Mundo online procura o servidor em `MUNDO_PADRAO` (vazio = "ainda não está no ar"). **Rota nova do `server.js` precisa de um plano para o Pages**, e **caminho novo de arquivo tem de bater maiúscula/minúscula** (o Pages diferencia; o Windows não). O `.gitignore` deixa de fora `saves/`, `mundo/`, os pacotes brutos e o `.exe`; publicar é `git push` (o Pages reconstrói sozinho).

**RECARREGAR PARA TODOS (`js/versao.js`, `assets/versao.json`)** — quem está com o jogo aberto segue no código antigo depois de um `git push`. Cada página lê `assets/versao.json` ao abrir e a cada minuto; quando o campo `versao` muda, ela avisa, grava o progresso, busca de novo os arquivos que carregou (`cache: 'reload'` — o Pages manda guardar tudo por 10 min, e sem isso a página recarregaria no código velho) e recarrega. **Quem decide é o push**: mudar `versao` recarrega todos em até um minuto; não mexer nela não incomoda ninguém. Mudança que altera o que VIAJA pela rede (o protocolo, o `MUNDO`) deve sempre subir com a `versao` nova — jogadores em versões diferentes no mesmo mundo é o que isto existe para evitar.

**O servidor de mundo no RENDER (`render.yaml`)** — plano grátis, que dorme sem visita e APAGA o disco a cada reinício. Por isso: `MUNDO_SAVES=nuvem` (o servidor não lê nem grava arquivo; o personagem mora em `masmorra.personagens`, migration 0002, lido e gravado pelo JOGO em `Mundo.lerDaNuvem`/`salvarNaNuvem`; o estado do mundo fica só na memória) e `FRENTE_EM` (o servidor não entrega o jogo: manda quem abrir o endereço para o Pages, para não gastar a franquia de tráfego). **Falhar em LER o personagem nunca vira "personagem novo"** — entraria zerado e gravaria por cima do de verdade. O `buildFilter` do `render.yaml` só reimplanta quando mudam os arquivos do servidor; `personagem_valido()` na migration é o `saveTorto()` em SQL — mudou um, mude o outro.

**`HOSPEDAR=1`** (servidor exposto para fora, atrás de túnel ou proxy): desliga `/__save` e `/__lan/*`. A defesa dessas rotas é "o pedido vem deste computador?" (`soDaqui`), e atrás de um túnel TODO pedido vem de `127.0.0.1`. Rota nova que confie em `soDaqui` precisa da mesma trava.

**Testar pela automação SEM estragar o save**: o jogo grava sozinho a cada 15 s e "Novo Jogo" APAGA `saves/progresso.json`. Antes de mexer: `game.salvar = () => {}` e `game.progresso = null; game.start()`. O `server.js` não manda cabeçalho de cache, e um Chrome de teste com perfil fixo pode rodar o `.js` VELHO depois de uma edição: desligue o cache (`Network.setCacheDisabled`). No mundo online, suba o servidor com `MUNDO_DIR` numa pasta temporária.

## Architecture

**`js/main.js` — `Game`** owns the renderer, scene, camera, and the single `loop()`. Every subsystem is constructed with `game` and reaches the others through it (`game.world`, `game.player`, `game.inventory`, `game.ui`, `game.sfx`, `game.effects`, `game.projectiles`, `game.all` = enemies + boss). Cross-system events are methods on `Game` (`onEnemyKilled`, `onPlayerDeath`, `rest`, `resetWorld`, `interact`, …). Game states are `loading` → `title` → `playing`. `game.menu` (`inventory`/`bonfire`/`pause`) freezes the simulation.
- Use `game.after(sec, fn)` for delayed game events rather than `setTimeout`. Its timers run in game time, so they respect menus, pause, and `hitstop`.
- Each frame: input → player/enemy updates → `separate()` (body pushing) → `world.resolve()` (wall collision) → projectiles/effects → camera.

**Asset pipeline (`js/assets.js`)**: All glTFs load up front. Characters come from two Quaternius UAL files (`UAL1`/`UAL2`), and their animation clips merge into `Assets.clips` by name. Dungeon props (KayKit) have to be listed in the `PROPS` array before `Assets.prop(name)` can use them; adding a new `.glb` without listing it breaks. Props get recolored in `tuneMaterials()`.

**Characters (`js/character.js`, `js/gear.js`)**: Every humanoid (player, skeletons, boss) is a `CharacterModel` cloned from the same UAL mannequin. Armor, bones, and weapons are procedural meshes built by `gear.js` **in the T-pose** and parented to skeleton bones, so they follow any animation. Animations are played by clip name (`model.play('Sword_Regular_A', …)`), and an unknown name only logs `Animação inexistente`. `initGear(renderer)` must run after assets load and before any model is built.
- **Os TRAJES vêm de ARQUIVO (30/09/2026)**: `buildOutfit(skel, kind)` veste o boneco com `assets/modelos/traje-<kind minúsculo>.json` quando `Assets.modelos` o tem (`vestirDoArquivo`: monta com `blocos.js` e prende cada peça no osso dela com `attach`, como o código fazia), e só cai no código (`buildOutfitDoCodigo`) sem o arquivo. Os arquivos saíram DESTE código pelo `importar-trajes.mjs` do editor, e um teste de lá garante que montam o mesmo boneco vértice a vértice. **Para mudar uma armadura, edite no Editor de modelo (botão "levar ao jogo")** — mudar o `gear.js` não muda nada enquanto o arquivo existir (reimporte com `importar-trajes.mjs ds --sobrescrever <tipo>`, que perde as edições do editor). Os ganchos `eyeMat` e `eyeAnchor` são garantidos mesmo que o traje editado os perca. Armas e escudos continuam no código.

**O GUERREIRO E O PROVADOR (`js/guerreiro.js`, `js/provador.js`, 03/10/2026)** — o CORPO DO JOGADOR, nos dois modos: o "Low Poly Axe Warrior" (loja da Unity), convertido por `ferramentas/guerreiro/converter.mjs` (three r185 próprio da pasta; conserta os ossos duplicados, a pose dos dedos, as peças de armadura giradas e o V das UVs) para `assets/guerreiro/guerreiro.glb` — o corpo nu em peças, três armaduras (`A1_`, `A2_`, `A3_` no nome da malha) e um esqueleto PRÓPRIO de 54 ossos. Faltando o `.glb`, todos ficam com o boneco antigo.
- **Retarget ao vivo**: o manequim UAL continua montado e animando (golpes, janelas de acerto, tudo igual), só que invisível; a cada quadro (`CharacterModel.update` → `CorpoGuerreiro.seguir`) cada osso do guerreiro recebe o giro que o osso UAL par (`PARES`) fez desde a pose T, e o quadril o deslocamento. A pose T do UAL vem do `Assets.baseScene` (nunca anima), por isso o corpo pode ser trocado no meio de um golpe. As armas vão para a mão do guerreiro (`pegada`) — e NÃO podem ser escondidas junto com o manequim (o bug da arma invisível).
- **O corpo** é um nome: `'nu'`, `'A1'`, `'A2'`, `'A3'` ou `'antigo'` (`CORPOS`). O escolhido fica no `localStorage` (`corpoGuardado`; da primeira vez, `'nu'`), o `CharacterModel` do jogador nasce com ele (`armadura`) e **Shift+G** abre o provador para trocar (`usarGuerreiro`). Ele VIAJA no instantâneo (`c`, `protocolo.js`): o `JogadorRemoto` veste o mesmo (`vestir`); rastro antigo sem `c` = boneco antigo. Inimigos seguem com o manequim.
- **A malha fundida** (`vestir` → `geometriaFundida`): as peças do corpo escolhido viram UMA `SkinnedMesh` com UM `Skeleton` (os ossos de cada peça renumerados para a ordem da cena), no material com cor de vértice (as peças sem cor ganham branco). Era ~30–39 chamadas de desenho por guerreiro (com sombra); ficou 1 para o corpo. A geometria de cada corpo é feita uma vez e DIVIDIDA por todos (não a descarte). As peças do arquivo (`pecas`) ficam escondidas, só como matéria-prima. O `JogadorRemoto.aplicarAparencia` pula malha escondida.

**O SAVE DE ANTES DA MATA (`MAPA_REV` em `save.js`)** — o save grava `jogador.mapa = 2`. Sem ele, é de antes de a mata abrir 14 colunas: itens no chão e a mancha da coluna 26 em diante andam 84 m, e o personagem acorda no acampamento NOVO — no Mundo online, todos; na Jornada, quem estava do acampamento para lá. Mapa mudou de novo de um jeito que move coisas? Suba `MAPA_REV` e trate a diferença ali.

**Attacks**: The `ATTACKS` table in `character.js` maps attack keys to a clip, an optional `from`/`to` sub-range, a `hit` window (in clip seconds, measured from blade-tip velocity), and an `arc`. Player weapons (`items.js`) and enemy configs (`ENEMY_TYPES` in `enemies.js`, `BOSS_CFG` in `boss.js`) refer to attacks by these keys. If you retime a swing, update the hit window too.

**World (`js/world.js`)**: The dungeon is generated from the ASCII `MAP` (one char = one `CELL` = 6 m, from `S = 1.5` scale; north = −Z; `[row, col]` addressing). Doors, cell bars, and fog are defined as edges between two cells in `SPECIAL_EDGES`. Content is data tables of `[row, col]` cells: `TORCHES`, `CHESTS`, `PICKUPS`, `MESSAGES`, and enemy spawns in `spawnEnemies()` (`enemies.js`). The world keeps `interactables` (typed `pickup`/`torch`/`chest`/`door`/`fog`/`bonfire`/`message`/`bloodstain`), and `Game.interact()` dispatches on that type. Enemies pathfind on the same grid.

**O TERRAÇO E O DRAGÃO (29/09/2026)** — um segundo andar ao ar livre, só alcançável pela escada escondida na floresta, com um chefe secreto.

**Entities**: `Player` (`player.js`) and `Enemy` (`enemies.js`) are state machines driven by `setState(name, data)`, with `stateT` as the elapsed time and `st` as per-state data. `Boss extends Enemy`. Enemies can start `dormant` (they rise from the ground when the player comes near). `resetWorld()` (on bonfire rest or death) calls `reset()` on every enemy.

**O SAVE (`js/save.js`, 01/10/2026)** — o progresso fica em `saves/progresso.json` (sem conta) ou `saves/conta-<id>.json` (com conta, mais a cópia em `masmorra.saves`; ver O ONLINE), gravado pelo `server.js` (rota `/__save[?conta=<uuid>]`: GET/POST/DELETE). É arquivo, e não localStorage, porque o launcher pode subir o jogo em outra porta. Grava ao descansar, ao fechar o menu da fogueira, ao renascer, ao vencer um chefe, a cada 15 s e ao fechar a janela (`sendBeacon`). Guarda atributos, almas, inventário, portas/baús/tochas (pela ORDEM em `world.doors`/`chests`/`torches`; reordenar as tabelas embaralha saves antigos), itens no chão, mancha de sangue, chefes vencidos e a posição (fora de luta de chefe; senão, a fogueira). Os inimigos comuns não entram, porque renascem a cada descanso. A tela de título mostra "Continuar", e "Novo Jogo" pede um segundo clique antes de apagar. Estado novo que deva sobreviver ao fechar precisa entrar em `coletar`/`aplicarProgresso`.

**O ONLINE (`js/rede/`, 01/10/2026)** — login OPCIONAL. Sem conta, tudo é offline como antes. O Supabase é o MESMO projeto do Duel Academy (mesmas contas), mas tudo da Masmorra fica no schema `masmorra`, para dar para desligar só ela (ver `supabase/README.md`; migrations em `supabase/migrations/`, aplicadas à mão no SQL Editor). Sem dependências: `rede/supabase.js` (cliente REST, sempre com `Accept-/Content-Profile: masmorra`) e `rede/realtime.js` (cópia adaptada do Duel Academy, só a face de transmissão + canal privado).
- **Nível 1 (feito)**: `Online` (`rede/online.js`, em `game.online`) liga, com conta, os `Fantasmas` (instantâneos via broadcast no canal `masmorra:mundo:<mapa>`, desenhados como `JogadorRemoto` translúcido), as `Mensagens` (texto livre ≤ 140, voto +1/−1, somem com −3; tecla **M** escreve; no leitor, **1/2** votam e **X** apaga a sua) e as `Mortes` (rastro de 5 s gravado sempre; vira mancha vermelha para os outros; tocar mostra o replay). Save por conta: `saves/conta-<id>.json` + `masmorra.saves`, e vence o mais novo. Mensagens e mortes são gravadas com o nome do mapa (`Assets.mapaNome`).
- **`rede/protocolo.js` é o formato único** do que viaja (o instantâneo `{v,id,x,y,z,g,a,s,t,d,e,st}`). TUDO que chega passa por `limparInstantaneo`, e dado torto é descartado, não corrigido. Os tipos de recado do co-op (`ACAO`, `GOLPE`, `DANO`, `MUNDO`, `EVENTO`) já estão reservados lá.
- **O terreno dos níveis 2/3 (co-op, PvP)**, já no código: `game.jogadores` (quem os inimigos perseguem e os projéteis atingem; hoje só o local); `Enemy.alvo`/`Dragao.alvo` via `game.alvoPara(pos, atual)` (o vivo mais perto, com folga para não ficar trocando). **A IA nunca lê `game.player`**: um `game.player` novo em código de inimigo quebra o co-op em silêncio. Mais: `netId` estável em cada inimigo (`e<i>`, `carrasco`, `wyrm`, `lacaio<n>`); `game.golpear(alvo, …)` como ponto ÚNICO de golpe do jogador (no co-op, o convidado manda `GOLPE` em vez de aplicar); `JogadorRemoto` já tem o contrato de alvo (`takeDamage` chama `aoSofrerDano`); `game.sessao` (null = sozinho). O plano é o anfitrião simular os inimigos e mandar `MUNDO`; cada um cuida da vida do próprio jogador. O que FALTA para o nível 2: a sala/convite, o menu que não pausa com `sessao` ativa, o `resetWorld`/fogueira compartilhados e o transporte (broadcast do Supabase serve para 2 jogadores; WebRTC com o Supabase só como sinalização é o passo seguinte).
- **A SALA E O DUELO (etapas 1 e 2, 02/10/2026)** — `rede/sala.js` (`game.sessao`), painel em `salaui.js` (tecla **O**). O anfitrião abre (código de 6 letras), o convidado entra, e cada um vê o outro SÓLIDO (`JogadorRemoto` "aliado"), com colisão (`separate`: o remoto não é empurrado). Cada um segue no PRÓPRIO mundo, com os próprios inimigos, até o co-op. Com alguém na sala, **abrir menu não pausa** (`congela` no loop).
  - **Os canos (`rede/transporte.js`)**: `internet` (broadcast Supabase, canal `masmorra:sala:<código>`, precisa de conta) e `local` (o `server.js` do ANFITRIÃO retransmite: SSE `/__lan/ouvir` + POST `/__lan/falar`, em `rede-local.mjs`; sem conta e sem internet). O anfitrião ouve nos dois. **Mesma rede**: o `OLA` do anfitrião leva os IPs dele (`/__lan/info`), o convidado sonda `http://ip:porta/__saude`, e se responder a sala troca para o cano local. **Descoberta sem internet**: cada `server.js` anuncia as salas abertas por UDP broadcast (porta 41234), e `/__lan/vizinhos` lista as dos outros ("Na sua rede" no painel). O servidor escuta em todas as interfaces, então **`/__save` só atende o próprio computador** (`soDaqui`). O Windows pode pedir para liberar o Node no firewall na primeira vez.
  - **O duelo**: convite → aceito (Y/N) → `game.esconderMundo(true)` (inimigos `active = false` e invisíveis), os dois frente a frente no `ARENA_CENTER`, contagem de 3 s, luta. **Quem ataca detecta** (o rival entra em `allEnemies()` só no duelo, e o golpe passa por `game.golpear` → `sessao.golpear` → `GOLPE_PVP`); **quem apanha decide** com o próprio `takeDamage` (rolou/bloqueou na tela dele, valeu; mais de 8 m do atacante é descartado). A vida do rival vem no instantâneo (`h`) e aparece na barra de chefe (`bossAtual`). Morrer no duelo não é morte (`onPlayerDeath` desvia para `sessao.perdi()`): sem mancha nem almas perdidas, e o inventário volta ao de antes. O save não grava durante o duelo.
- **O CO-OP (etapa 3, 02/10/2026)** — `rede/coop.js` (`sessao.coop`). "Chamar para o meu mundo" no painel: **quem chama é o DONO do mundo**, e o outro entra nele (o desenho do Dark Souls). Os convites de duelo e co-op são o mesmo mecanismo na sala (um por vez: `convidei`/`convite` com `tipo`).
  - **No dono, o mundo é de verdade**: o convidado entra em `game.jogadores` (os inimigos o perseguem, os projéteis o acertam), e o `takeDamage` do `JogadorRemoto` vira `DANO` para ele. O dono manda o `MUNDO` a cada 100 ms: o retrato de cada inimigo com `netId` (`retratoDoInimigo`/`lerRetrato` em `protocolo.js`; o dragão vai com a pose das peças em `extra`), as portas/névoa e a barra do chefe.
  - **No convidado, `game.marionetes = true`**: `Enemy.update` e `Dragao.update` desviam para `updateMarionete` (só repetem o retrato, interpolado pelo `Interpolador` de `remoto.js`; nada de IA, dano ou alma). Os lacaios do Carrasco que o dono invoca são criados como marionetes. O golpe do convidado vira `GOLPE` (`game.golpear` → `sessao.golpear` → `coop.golpear`) e quem aplica é o dono; cada morte manda `EVENTO almas` ao convidado.
  - **O mundo do convidado não muda**: portas e névoa copiam as do dono (`world.aplicarPassagens`, com `closeDoor`/`closeFog`) e voltam no fim (`voltarParaCasa`); ele não pega item nem abre baú, porta ou fogueira (`Game.interact`); o save não grava com `marionetes` ligado, só depois (com as almas). O Carrasco só acorda quando o DONO entra na arena (`onEnterArena` não faz nada no convidado; `Boss.podeMirar` só aceita quem está na arena).
  - **Fim**: o dono morre, descansa (`rest`) ou volta à fogueira (`teleportHome`); o convidado morre (`morriComoConvidado`: volta sem perder nada) ou vai embora; 6 s depois de um chefe cair; alguém sai da sala.
  - **Projéteis** (orbe, onda, bomba) criados no co-op viram `EVENTO proj`, e o outro lado cria uma cópia `visual: true` (voa e explode, não fere).
  - O que NÃO viaja (aproximações aceitas): os efeitos de partícula do Carrasco (fase 2, invocação), os sons dos inimigos além do golpe, o orbe visual não persegue ninguém. Pela internet, o co-op são ~18 recados/s — conta na cota do Realtime do Supabase; pela rede local não custa nada.
- **O CHAT GLOBAL (`rede/chat.js`, 03/10/2026)** — é o MESMO chat global do Duel Academy: a tabela `public.mensagens` (migration 0040 de lá), lida por `chat_global` e escrita por `enviar_mensagem` (teto de 500 letras e limite de ritmo valem no banco). É a ÚNICA coisa da Masmorra fora do schema `masmorra` — por isso `req(..., { schema: 'public' })` e a face `ouvirMudancas` do `realtime.js` (tópico próprio, `masmorra-chat`). Liga em `Online.comecarPartida` (logado, nos dois modos) e fica SEMPRE à vista (`#chat` no HUD, canto de baixo à DIREITA, sobre as almas — à esquerda fica a cruz dos itens e no meio a barra do chefe): a nova entra embaixo, as velhas sobem, 60 na tela. **Enter** abre a linha, Enter manda, Esc desiste (o Esc solta o mouse antes de chegar à caixa, e o `pointerlockchange` trata isso como "desistir", não "pausar"). Entrega: Realtime + releitura a cada 8 s.
- **A CRUZ DOS ITENS (`#equip`, 03/10/2026)** — como no Dark Souls: quatro losangos encostados (em cima vazio, o lugar da magia; esquerda = mão esquerda, com o tempo da tocha na ponta esquerda; direita = mão direita; embaixo = item rápido, com a quantidade e o nome ao lado em `#equip-nome`) e a cruzinha `#dpad` no meio. As posições são absolutas e saem da conta no comentário do `style.css`.
- **O CELULAR (`js/toque.js`, 03/10/2026)** — liga com `ehToque()` (`pointer: coarse`, ou `?toque` na URL para testar no PC) e põe `body.toque`. **Não há regra de jogo nova**: os botões apertam as MESMAS teclas/botões do mouse (`Input.apertar`/`soltar`/`mouseApertar`/`mouseSoltar`), e o joystick dá `Input.eixo` (lido em `Player.moveInput`, com zona morta). Metade esquerda = joystick que nasce sob o polegar; o resto = câmera (`SENS_CAMERA`); combate no canto de baixo à direita; menu/itens/grupo/chat/escrever em cima; a cruz dos itens e o aviso "E ..." se tocam. Botão novo = uma linha em `BOTOES`. O que abre o TECLADO (chat, mensagem) é chamado DENTRO do toque (`acao`), senão o navegador não dá o foco. `Input.requestLock` não faz nada no toque. **Tela deitada**: o primeiro toque pede tela cheia + `screen.orientation.lock('landscape')` (Android; o iPhone não tem) e, em pé durante o jogo, `#girar` pede para girar. Todo o CSS do celular fica sob `body.toque` — o PC não muda. Os menus ganham `#toque-fechar` (o inventário só fechava por tecla).
- **DESEMPENHO E QUALIDADES GRÁFICAS (`js/graficos.js`, 03/10/2026)** — backup dos gráficos de antes na tag git `graficos-antes-da-otimizacao`. **Alto = o visual de antes**; Médio (sombra da tocha 256 px redesenhada a cada 2 quadros, 5 luzes, resolução até 1,25×, 70% das partículas) e Baixo (sem sombra, 3 luzes, resolução 1×, sem o filtro de cor do canvas, sem antisserrilhado — que só vale ao reabrir —, 45% das partículas). Escolha no menu de pausa, guardada no `localStorage`; o celular começa no Médio. Três otimizações valem para TODAS e não mudam nada do visual (conferido pixel a pixel contra a tag):
  - **A armadura fundida** (`fundirTraje` em `character.js`): os ~84 blocos de cada boneco (traje do arquivo) viram uma `SkinnedMesh` por tipo de material, cada vértice preso ao seu osso, com a cor do bloco nos vértices. Ficam de fora o material dos olhos (`eyeMat`, animado) e o transparente. **Código que procure um bloco da armadura pelo nome depois de montado não o acha mais** — mexer num bloco é no traje (Editor de modelo), não em jogo.
  - **A decoração em lotes** (`World.agruparDecoracao`): peças iguais do `decor.json` na mesma região de 24 m viram um `InstancedMesh`. Peça de decoração que precise mexer depois de pronta tem de ficar fora dos lotes.
  - **Luzes em orçamento FIXO** (`World.distribuirLuzes`): sempre o mesmo número de luzes de cenário visíveis (as mais perto, as acesas primeiro). Mudar o número de luzes visíveis recompila todos os shaders — nunca ligue/desligue `visible` de luz fora daí. E os shaders são compilados no carregamento (`Graficos.aplicar` → `renderer.compile`).
  - A sombra da tocha é redesenhada por `Graficos.update` (`needsUpdate`), não pelo `autoUpdate`.
- **QUEBRÁVEIS (03/10/2026)** — `QUEBRAVEIS` no `world.js` diz que peças do `decor.json` quebram (barris, caixotes, sacos, balde, garrafa, banquinho) e com que cor e quantos pedaços; `SAQUES`, o que pode cair (sorteia UM; `null` = nada). Eles ficam FORA dos lotes da decoração e são chamados pela posição no `decor.json` (`q.i`, igual em todas as máquinas). Quebra o golpe do jogador (`Player.updateAttack`) e a bomba (`Projectiles.explodeBomb`), sempre por `Game.quebrar` (o que cai é de quem quebrou; `sessao.aoQuebrar` avisa a rede). `World.quebrar` é só visual + colisão (some o círculo de colisão; os pedaços voam, quicam e afundam em ~16 s). **A VEGETAÇÃO também se corta** (`cfgQuebravel`: `Bush_*`, `Grass_*`, mato): solta folhas (partículas verdes) em vez de lascas, é LOCAL (só quem cortou vê; não entra no `estadoPassagens`) e rebrota `REBROTA_S` (90 s) depois com o jogador a mais de 14 m. Ela CONTINUA nos lotes da decoração: cortar põe a cópia dela no `InstancedMesh` em escala 0 (`q.instancias`, `World.mostrarQuebravel`). Os quebrados (não locais) viajam em `estadoPassagens().quebrados`, junto das portas: **Jornada**: voltam ao descansar/morrer (`resetWorld` → `restaurarQuebraveis`); **co-op**: são do dono (o convidado avisa com `EVENTO quebrar`); **Mundo online**: de todos — quem não simula manda `ACAO quebrar` (8 m de tolerância, como a porta), o simulador marca e o relógio (`Mundo.quebrados`, no `est`) os devolve inteiros 3 min depois, sem ninguém a 22 m.
- **A COMIDA NO LUGAR DO ESTUS (03/10/2026)** — o Estus SAIU: a cura é comida (`use: 'comer'` em `items.js`: `cura` na hora, `regen` {porSeg, dur} aos poucos, `efeito` {tipo, dur} — `folego` (vigor), `fortaleza` (+15% defesa), `furia` (+20% dano), lidos nos getters do `Player` e mostrados em `#buffs`). Ingredientes vêm dos quebráveis e dos inimigos (`drops`). Save antigo com Estus ganha 5 Pães Duros (`aplicarProgresso`); o personagem novo do MMO nasce com 3.

**OS DOIS MODOS e O MUNDO ONLINE — o MMO (02/10/2026)**. O plano, o que falta e as armadilhas estão em `TASKS-MMO.md`.
- **`game.modo`**: `'offline'` (a Jornada: tudo o que está descrito acima) ou `'mmo'` (o Mundo online). Quem escolhe é o botão da tela de título (`entrarNoMundo`). As diferenças têm NOME em `js/modo.js` (`REGRAS`), e o código pergunta `game.regras.<nome>` — `pausa`, `mundoReinicia`, `visitaSoAjuda`, `lutaDoMundo`, `fantasmas`, `espalharAoAcordar`. Um `if (game.modo === 'mmo')` novo espalhado pelo jogo é o que esse arquivo existe para evitar.
- **O acampamento** (`CAMP_POS`, colunas 40–53 do mapa `floresta`, que tem 55) é onde o personagem novo do MMO nasce, com a adaga (`Game.comecarFora`). **As fogueiras são duas** (`FOGUEIRAS` no `world.js`; `world.retorno(id)` diz onde se acorda) e `player.fogueira` é a última em que se descansou — `respawn`, `teleportHome` e o save usam isso. A decoração de lá sai do `decorar-acampamento.mjs` do editor (alvo `ds-aqui` neste PC), que só toca da coluna 26 em diante — **ajuste-o para a 40 antes de rodá-lo de novo** (a mata abriu 14 colunas antes do acampamento), senão ele apaga a decoração da mata.
- **O servidor (`servidor-mundo.mjs`, rotas `/__mundo/*`)** não roda o jogo: confere a conta (token do Supabase em `/auth/v1/user`; `MUNDO_AUTH=teste` aceita `teste:<Nome>`), dá um bilhete, retransmite por SSE + POST e ROTEIA por tipo — `pos`/`mundo` aos outros, `golpe`/`acao` só ao simulador, `dano` só ao alvo, `evento` do simulador a todos (ou ao `para`). Guarda o save de cada personagem (`mundo/personagens/<id>.json`, conferido por `saveTorto`) e o estado do mundo (`mundo/estado.json`).
- **Um dos CLIENTES simula os inimigos** (`Mundo.souSim`; `game.marionetes` é sempre o contrário). O servidor escolhe o mais antigo com a janela à vista e TROCA quando ele sai, trava (2,5 s sem `mundo`) ou esconde a janela. Quem assume recebe o último retrato de cada inimigo e segue dali: `Mundo.assumir` → `Enemy.retomar` / `Boss.retomar` / `Dragao.retomar`. Inimigo novo com estado próprio precisa do seu `retomar`, ou volta para casa inteiro a cada troca.
- **O mundo não reinicia** (`regras.mundoReinicia` falso): `rest()` e a morte NÃO chamam `resetWorld()`. Quem cuida é `Mundo.tique`, uma vez por segundo, só no simulador, com o relógio do SERVIDOR (`mundo.agora()`): inimigo renasce 3 min depois (sem ninguém a 22 m), chefe ressurge em 15 min com a névoa fechando, chefe acordado sem ninguém vivo na luta volta a dormir. Os relógios viajam no `est` do `mundo` e o servidor os guarda — sobrevivem à troca de simulador e ao mundo vazio.
- **De todos × de cada um**: inimigos, portas, névoa e chefes são de todos (a porta que um abre vira `acao` para o simulador). Baús, itens no chão, tochas da parede, mancha de sangue e almas são do PERSONAGEM e ficam no save dele — por isso `aplicarProgresso` pula portas e chefes no MMO. As almas e o que cai vão para quem bateu ou estava a 25 m (`Mundo.repartir`, chamado por `onEnemyKilled`); o prêmio do chefe é `Game.premiarChefe`, em cada um que lutou.
- **A luta de chefe é de quem está NELA** (`Mundo.atualizarLuta`): `game.bossFight`, a barra e a música ligam só para quem está na arena/terraço com o chefe acordado. No offline continuam globais (`regras.lutaDoMundo`).
- **O contrato de `game.sessao`** (a `Sala` no offline, o `Mundo` no MMO): `outros` (os bonecos sólidos), `update(dt)`, `golpear(...)`, e os ganchos opcionais `repartir`, `aoVencerChefe`, `aoEntrarNaArena`, `aoAbrirPorta`, `aoProjetil`, `salvar`. O jogo os chama com `?.` — método novo num, e não no outro, não pode quebrar o outro modo.
- **`transporteMundo`** (`rede/transporte.js`) manda UM POST por vez e junta o resto em lote: vários POSTs em paralelo chegam fora de ordem. `troca: true` (posição, retrato) substitui o que ainda está na fila.
- O que NÃO é: à prova de trapaça (quem simula é um cliente). O que NÃO foi feito: ver `[ ]` no `TASKS-MMO.md` (hospedar pela internet, o dragão com dois jogadores, portas que fecham sozinhas, instanciar o cenário).

**A GUARDA E O ESCUDO NAS COSTAS (`Player.guarda`, 03/10/2026)** — com escudo, a guarda é o escudo (`Idle_Shield_Loop`); com arma de DUAS MÃOS (`twoHanded`), o escudo vai para as COSTAS (`CharacterModel.equipCostas`, preso ao `spine_03`/`Spine001`, `costasMatrix`) e a guarda é a própria arma (`Sword_Block` parado no quadro 0,45 s, estabilidade `guarda` do item — o espadão 0,5). Com a tocha acesa na esquerda o botão direito segue sendo o golpe dela (sem guarda). Antes, a arma de duas mãos simplesmente sumia com o escudo e não bloqueava. O `JogadorRemoto` faz o mesmo com as costas.
- **AS DUAS MÃOS** (`CharacterModel.segurarComAsDuas`, ligado por `model.duasMaos`): os clipes do UAL são de uma mão, então, depois da animação (e do retarget), um IK de dois ossos (`ikDoisOssos`, giros no mundo) leva a mão esquerda ao cabo, `ABAIXO_NO_CABO` (11 cm) abaixo da direita, na MESMA pegada com que ela segura a tocha (`pegadaEsquerda`: dá o lugar do pulso e o giro da mão), com os dedos fechados na pose do `Idle_Torch_Loop` (`fecharDedosEsquerdos`, no manequim, antes do retarget); quando o cabo está longe demais para o braço esquerdo, o braço direito traz a arma para perto do corpo (a mão mantém o giro: a lâmina só anda). O cabo fica SEMPRE na frente do peito (`FRENTE_MIN`, nos eixos do tronco) e os cotovelos apontam para fora e para baixo (o `polo` do IK): sem isso o braço esquerdo atravessava o corpo até uma espada do lado direito. Fora em `MAO_OCUPADA` (comer, item, caído, descansando) e com a tocha; o peso entra e sai suave. O remoto liga pelo item que viaja (`d`/`e`) e pelo estado.

**Items/inventory**: `ITEMS` in `items.js` holds every item definition plus its inline SVG icon. `Inventory` tracks counts and equipped slots (right hand, left hand, rings, quick belt). The torch is a left-hand item with a burn timer (`TORCH_LIFE`, which only counts down while lit in hand), and it swaps with the last shield in `inv.lastShield`.

**Other**: `combat.js` holds shared math helpers (`flatDist`, `yawTo`, `angleToTarget`, `turnTowards`) plus the particle `Effects` and `Projectiles`. `audio.js` synthesizes all sound with WebAudio, so there are no audio files. `ui.js` drives the DOM HUD and menus declared in `index.html`.
